# Timeline Layout Algorithm – Plain English Explanation

## Goal

Create a **vertical (top-to-bottom) timeline** where each timeline node can have multiple cards connected to it.  
The layout must be **balanced, readable, and collision-free**, regardless of how many cards each node has.

The timeline should grow **downwards**, and each node should automatically adjust its position based on how much space its own cards and the previous node’s cards occupy.

* * *

## Core Idea (High Level)

Think of each timeline node as occupying a **vertical influence area**.

This influence area depends on:

* How many cards belong to the current node
    
* How many cards belonged to the previous node
    

Before placing a node, we first calculate **how much vertical space is required** so that:

* Cards from different nodes never overlap
    
* The layout remains symmetric and visually balanced
    

* * *

## Step 1: Understand Card Distribution

Each node can have multiple cards.

These cards must be placed:

* Half above the node
    
* Half below the node
    

If the number of cards is **odd**, one card stays exactly at the same vertical level as the node.

Examples:

* 1 card → center only
    
* 2 cards → one above, one below
    
* 3 cards → one above, one center, one below
    
* 4 cards → two above, two below
    

This symmetry is **mandatory** and must always be preserved.

* * *

## Step 2: Treat Cards as Vertical Weight

When placing a node, we care only about:

* How many cards appear **below** the previous node
    
* How many cards will appear **above** the current node
    

These two together determine the **minimum vertical gap** needed between nodes.

You do **not** need to know exact positions yet — only how much space they will occupy.

* * *

## Step 3: Decide the Distance Between Two Nodes

To place the current node:

1. Look at the previous node
    
2. Count how many cards from that node extend downward
    
3. Look at the current node
    
4. Count how many cards from the current node extend upward
    
5. Add:
    
    * Space required for those cards
        
    * Space between cards
        
    * A fixed minimum gap so nodes never look crowded
        

This combined space defines how far **down** the current node must be placed from the previous one.

* * *

## Step 4: Place the Node Center

Once the vertical distance is decided:

* Place the node so its **center** sits at that position
    
* All positioning for that node is calculated relative to this center
    

The node center is the anchor for everything else.

* * *

## Step 5: Place the Date Card

Each node has a **date card** (or equivalent central card).

This card:

* Must be vertically centered on the node
    
* Acts as the reference point for placing all other cards
    

Half of the date card sits above the node center, and half below.

* * *

## Step 6: Place the Child Cards

Using the date card as the anchor:

* Cards meant to go **above** are stacked upward, evenly spaced
    
* Cards meant to go **below** are stacked downward, evenly spaced
    
* If there is a center card (odd case), it aligns exactly with the node
    

Spacing between cards must be consistent and configurable.

* * *

## Step 7: Draw Connections

Connections should be drawn in layers:

1. Node → Date card  
    (short, clean connection)
    
2. Date card → Each child card  
    (each card has its own connector with consistent spacing)
    

Connections should never overlap cards and should respect spacing rules.

* * *

## Step 8: Handle Special Cases

* **No cards on a node**  
    The node still appears, but only minimal spacing is used before the next node.
    
* **First node**  
    Starts at a predefined top position.
    
* **Hidden or skipped sections**  
    If a card or section is hidden, it should not contribute to spacing calculations.
    

* * *

## Step 9: Rendering Order Matters

For clean visuals:

1. Calculate positions for all nodes first
    
2. Then place date cards
    
3. Then place child cards
    
4. Then draw connectors
    
5. Finally render visuals
    

Layout must be calculated **before** anything is drawn.

* * *

## Mental Model (Important)

Imagine stacking **invisible vertical blocks** above and below each node.

Before placing a node, make sure:

> “There is enough empty vertical space so the invisible blocks from this node and the previous one never touch.”

If you follow that rule, the layout will always be clean.

* * *

## What This Guarantees

* No overlapping cards
    
* Symmetric layout
    
* Predictable spacing
    
* Easy animation
    
* Easy theming
    
* Easy hiding/skipping of components

# Timeline Layout Algorithm – Plain English Specification

_(Style-Driven & Technology-Agnostic)_

* * *

## Purpose

Design a **top-to-bottom timeline layout** where each timeline node can contain multiple cards, arranged symmetrically and without overlap.

The layout must be:

* Predictable
    
* Visually balanced
    
* Easy to modify
    
* Entirely driven by configurable style values
    

No layout dimensions should be hardcoded.

* * *

## Style-Driven Design (Very Important)

**Every visual and spacing decision must come from a style configuration**, not from fixed values.

The style must control:

* Card height
    
* Card width (if applicable)
    
* Spacing between cards
    
* Node size (diameter / height)
    
* Spacing between nodes
    
* Distance between node and date card
    
* Distance between date card and child cards
    
* Connector spacing and offsets
    

Changing the style should be enough to:

* Make the timeline more compact
    
* Make it more spacious
    
* Completely change its visual density
    

The layout algorithm must **read these values** and adapt automatically.

* * *

## Core Elements

### Timeline Node

A vertical milestone placed on the main spine.

* Has a configurable size (height/diameter)
    
* Acts as the anchor point for layout calculations
    

* * *

### Date Card

A central card associated with a node.

* Its height is configurable via style
    
* It is always vertically centered on the node
    
* It is the reference point for distributing child cards
    

* * *

### Child Cards

Cards associated with a node.

* Each card has a configurable height
    
* Spacing between cards is configurable
    
* Cards are positioned symmetrically above and below the date card
    

* * *

## Layout Philosophy

Each node occupies a **vertical influence zone** based on:

* How many cards it has
    
* How large those cards are
    
* How much spacing the style defines
    

Before placing a node, the algorithm must ensure there is **enough vertical space** so that:

* Cards from different nodes never overlap
    
* Visual symmetry is preserved
    

* * *

## Card Distribution Rules

For each node:

* Cards are split evenly above and below the date card
    
* If the number of cards is odd:
    
    * One card is placed at the same vertical level as the node
        
    * Remaining cards are split evenly above and below
        

This rule must always be followed, regardless of card count.

* * *

## Vertical Spacing Between Nodes

When placing a node:

1. Look at the previous node
    
2. Determine how many of its cards extend downward
    
3. Look at the current node
    
4. Determine how many of its cards will extend upward
    
5. Combine:
    
    * Height of those cards
        
    * Spacing between those cards
        
    * A minimum node-to-node spacing from the style
        

This combined value determines how far below the previous node the current node should be placed.

* * *

## Node Positioning

* Nodes are positioned using their **center point**, not their top
    
* The node’s size is defined by the style
    
* The node center acts as the vertical anchor for:
    
    * The date card
        
    * All child cards
        

* * *

## Date Card Positioning

* The date card is always vertically centered on the node
    
* Half of the date card appears above the node center
    
* Half appears below
    
* The horizontal distance from the node to the date card is style-controlled
    

* * *

## Child Card Positioning

From the date card:

* Cards above are stacked upward
    
* Cards below are stacked downward
    
* Each card respects:
    
    * Configurable card height
        
    * Configurable spacing
        
    * Configurable distance from the date card
        

If there is a center card (odd case), it aligns exactly with the node center.

* * *

## Connectors

Connections are drawn in a structured way:

1. From node to date card
    
2. From date card to each child card
    

Connector lengths, offsets, and spacing must be style-configurable.

Connectors should never overlap cards.

* * *

## Special Situations

### Node with No Cards

* Node still renders on the spine
    
* Only minimal node-to-node spacing is applied
    
* No date card or child card layout is required
    

* * *

### Hidden or Skipped Cards

* Hidden cards must not participate in spacing calculations
    
* Only visible cards influence layout
    

* * *

## Rendering Order

For correct visuals:

1. Calculate all node positions
    
2. Calculate date card positions
    
3. Calculate child card positions
    
4. Calculate connectors
    
5. Render visuals
    

Layout must be fully resolved before rendering begins.

* * *

## Key Principle (Summary)

> The layout is not based on fixed coordinates.  
> It is based on **measured vertical influence**, driven entirely by style configuration.

If the style changes, the layout must still work correctly without modifying the algorithm.

* * *

## Expected Outcome

This approach guarantees:

* No overlaps
    
* Symmetric layouts
    
* Easy theme changes
    
* Easy hiding/skipping of elements
    
* Consistent behavior across datasets
